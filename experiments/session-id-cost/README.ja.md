# session_id を載せる場所の負担（実測）

状態: **非規定の実験**（2026-09-24）。[セッションと排他](../../docs/session-and-exclusivity.ja.md) の未決 1
（session_id を載せる場所と長さ、64 byte フレームでの負担）の入力。決めてはいない。

## 測ったもの

v0 の core ping（データをそのまま返す）の往復時間を、payload の長さごとに測った（`rtt_by_size.py`）。
要求 1 回あたりの固定費と、1 byte あたりの費用が分かる。

| 経路 | 固定費（1 往復） | 1 byte あたり（往復） | 4 byte を片道に足したとき |
|---|---|---|---|
| classic ESP32 の UART 115200 bps（CH340 + usbip、V003 治具） | 4.4 ms | 170 µs（理論値 174 µs） | +0.35 ms |
| ESP32-P4 の USB-Serial/JTAG（usbip、X035 治具） | 0.48 ms | 5.5 µs | +11 µs |

長さごとの中央値（µs）:

| payload | 0 | 4 | 8 | 16 | 32 | 64 | 128 | 256 | 480 | 900 |
|---|---|---|---|---|---|---|---|---|---|---|
| UART 115200 | 3,911 | 4,600 | 5,461 | 6,938 | 9,828 | 15,660 | 26,116 | 46,410 | 83,939 | — |
| P4 USB | 450 | 466 | 489 | 597 | 637 | 880 | 1,221 | 1,910 | 3,125 | 5,410 |

UART は 2 回測って、当てはめが 4.4 ms + 170 / 166 µs per byte で一致（表は 2 回目）。P4 は 100 回ずつ。
UART の 0 → 4 byte の差は 0.69 ms（往復で 8 byte 分の理論値 0.69 ms と一致）。

## 作業に当てはめた見積もり（u32 の session_id を毎回載せる場合）

| 作業 | 経路 | 負担 |
|---|---|---|
| V003 16 KB の書き込み（F4、512 byte フレーム、約 52 要求） | UART | 約 18 ms / 2.88 秒 = 0.6 % |
| 同じ作業を 64 byte フレームの低スペックで | UART | 1 フレームのデータが 50 → 46 byte に減り、フレーム数も増える。約 0.25 秒 / 約 3.5 秒 = 約 7 % |
| X035 62 KB の書き込み（F4、約 500 要求） | USB | 約 6 ms = 0.3 % |
| コンソールのポーリング（小さな要求） | UART | 1 回 約 5 ms に +0.35 ms（7 %） |
| 同上 | USB | +11 µs（2 %） |

## 分かったこと

- USB では、どこに載せても負担は無視できる。
- 効くのは **UART + 小さいフレーム** と **小さな要求を繰り返すポーリング** だけで、それでも 7 % 程度。
- ヘッダに載せるか payload に載せるかの差は、「載せない要求を作れるか」の差になる。ロックなしで使える読むだけの要求
  （confirm、list、describe、コンソールの読み出しを許すなら、それも）で省ければ、ポーリングの負担は消える。

## 実行

```sh
cd <oep-client-python>
uv run python <この dir>/rtt_by_size.py PORT [REPS]
```
