# Open Embedded Probe — ロジック / アナログのキャプチャ

状態: **提案**（2026-09-25）。前半はロジアナとしての設計で、OEP から切り離して読める。後半でそれを
`oep.fixture.capture`（ロジック）と `oep.fixture.analog`（アナログ）の操作に落とす。番号と幅は仮の値。
根拠の実測は [§7](#7-根拠の実測2026-09-25)。アナログは実測がまだない（§2.6）。

## 1. 何を作るか

probe の空いている GPIO で、target の信号を時系列に取る。単体のロジアナ（Saleae、sigrok の fx2lafw など）と同じ
使い方ができることを目標にし、そのうえで probe ごとの差（ハードウェアで取れるか、ソフトウェアで回すか、どれだけ
ためられるか）を宣言で表す。

- 解析（UART / I2C / SPI のデコード）と表示は host が持つ。probe はサンプルを取ってためて渡すだけ。
- 時刻はサンプルの番号から出す。サンプルごとの時刻は持たない。
- 保存形式（sigrok の `.sr`、VCD）への変換も host。

## 2. ロジアナとしての設計

### 2.1 構成要素

| 要素 | 決めること |
|---|---|
| ライン | 取る信号の本数（1〜16）。どのピンを使うかは plan で割り当てる |
| サンプルクロック | 何 Hz で取るか。**要求と実際が違う**（§2.2） |
| サンプルの形 | 1 サンプル = ライン数ぶんのビット。probe が 1/2/4/8/16 ビットに詰める |
| バッファ | probe の中にためる場所。大きさで取れる時間が決まる |
| トリガ | いつ取り始めるか（§2.4） |
| 取得モード | 1 回だけ取るか、繰り返すか、取り続けるか（§2.3） |
| 転送 | ためたものを host が読む（§2.5） |

### 2.2 サンプルクロック

範囲で表せない機材が多い。

| 実装 | 実際のレート | 刻み | 揺れ |
|---|---|---|---|
| ESP32-P4 PARLIO | 源 ÷（整数 + 分子/分母）。源は 160 MHz / 40 MHz / RC | 範囲内ならほぼ任意 | 分数のとき源 1 周期（160 MHz で 6.25 ns） |
| classic ESP32 のソフトウェア sampler | 240 MHz ÷ 整数 | 240M/n の離散値。上の方ほど粗い | ループの揺れ |
| RP2 の PIO（未実装） | sysclk ÷（整数 + 分数/256） | ほぼ任意 | 分数のとき sysclk 1 周期 |

そこで次のようにする。

- **host は欲しいレートを言い、probe は実際に使うレートを返す。** 実際のレートは分数（分子 Hz / 分母）で返す。
  240 MHz / 121 のような値を丸めずに表すため。
- **設定せずに問い合わせるだけの形を持つ。** UI がレートの候補を作るときに、試しに聞けるようにする。
- **範囲外は probe が拒否する。** P4 のドライバは範囲外の要求をエラーにせず源クロックのまま取る（§7）ので、
  probe が自分で検査する。
- 揺れの種類（なし / 分数分周 / ソフトウェア）を返す。host がエッジの時刻の誤差を見積もるため。
- ライン数によって上限が変わる実装がある。上限は configure の拒否か、問い合わせで分かる。

### 2.3 取得モード

| モード | 動き | バッファの使い方 | 取りこぼし |
|---|---|---|---|
| **ワンショット** | 指定サンプル数を取ったら止まる。転送はあとでゆっくり | 1 回ぶん | なし（取り終わるまで読まない） |
| **リピート** | ワンショットを何度も取る。host が読み終えた区画から再利用する | 区画（セグメント）の並び | **なし**。空き区画がなければ待つ（待った時間は記録する） |
| **ストリーミング** | 止めずに取り続ける。host は追いかけて読む | リング | 読むのが遅れると古いものから上書き（上書きした量は記録する） |

**ワンショット**が基本機能で、どの実装も持つ。リピートとストリーミングは任意。

ワンショットには、**取っている間に probe が他の処理をできるか**のフラグを付ける。

- できる（P4 の PARLIO は DMA で取る）: 取っている間も debug の線や UART、コンソールの吸い出しが動き、OEP の
  要求にも答える。
- できない（classic ESP32 の sampler は割り込みを止めて CPU で回す）: 取っている間 probe は何にも答えない。
  host は開始の応答で**止まる時間の見込み**を受け取り、その間は要求を送らない。コンソールの吸い出しも止まるので、
  その間に target が詰まることがある。

リピートとストリーミングの違いは、**あふれたときにどちらを守るか**。

- リピートは取れたものを守る。host が「ここまで読んだ」と返すまで区画を上書きしない。あふれたら取得を止めて待ち、
  次の区画の開始時刻で空白が分かる。
- ストリーミングは新しいものを守る。host の読んだ位置を probe は知らない（読むだけでは状態を持たない）ので、
  コンソールと同じく古いものから押し出し、押し出した印を残す。

区画の間には、どの実装でも止まる時間（再開までの時間）がある。**区画の間は連続を約束しない**。各区画は開始時刻を
持ち、host はそれで並べる。区画の中は連続を約束する。

### 2.4 トリガ

| トリガ | 内容 | 必須か |
|---|---|---|
| 即時 | 開始の要求で取り始める | 必須 |
| レベル / エッジ | 1 本のラインが指定のレベルになる、または指定のエッジで取り始める | 任意 |
| パターン | 複数ラインの組み合わせ | 任意 |
| プリトリガ | トリガより前の N サンプルも含める | 任意（取り続けながら待つ必要がある） |

実装によってできることが大きく違う（P4 の PARLIO はパターン検出の回路を持たない、PIO は `wait` 命令で 1 本の
レベル / エッジを待てる、ソフトウェア sampler はループの中で比べられるが上限が下がる）。**持つトリガの種類を宣言**
し、持たないものは拒否する。host 側で取ってから探す方法もあるので、probe が持たなくても使える。

外部の契機（別の fixture のピンを動かした瞬間など）は、host が開始を送ればよい。精度が要るなら、その契機の
ラインもキャプチャに含めて host が探す。

### 2.5 転送

- **host が読みに行く。** probe から勝手に送る通知はない（[コンソールのストリーム](console-stream.ja.md)と同じ）。
- **位置で読む。** 読んでも消えない。応答が失われても、同じ位置でもう一度読めば同じデータが返る。
- **複数の読み出しを同時に出してよい。** probe は届いた順にバッファから直接送る。読み出しごとに probe が
  メモリを持つ必要はない。
- **読み出しはロックなし。** 状態を変えないので、他の host のロック中でも読める。

速さは「1 回で読める量 × 同時に出せる本数」で決まる（§7.2）。HS では 16 KiB 以上 × 4 本以上で上限に届く。
そのため、1 回で読める量は **probe が frame に組み立てなくても送れる**大きさにする。応答の本体はバッファから
直接流す。

ストリーミングが続くかどうかは host が計算する。`レート × 詰めたビット幅 ÷ 8` がリンクの速さを超えれば、
そのうち押し出しが起きる。

| リンク | 実測の上限 |
|---|---|
| UART 115200（classic ESP32） | 約 11 KiB/s |
| USB-Serial/JTAG（P4、FS） | 約 810 KiB/s |
| HS vendor bulk（P4、usbip 経由、ハブ経由） | 約 34.8 MB/s |

### 2.6 アナログ

ADC で電圧を時系列に取る。音声の 48 kHz 程度までなら多くのマイコンで取れる。**取得モード（§2.3）、区画（§4）、
転送（§2.5）はロジックと同じ**で、違うのはサンプルの中身と、チャネルの取り方と、値の意味の 3 つ。

| 項目 | ロジック | アナログ |
|---|---|---|
| 1 サンプル | ライン数ぶんのビット | チャネルごとに ADC の値（9〜16 ビット）を 16 ビットに入れる |
| 複数本の取り方 | 同時 | **多くは順番に切り替え**（マルチプレクサ）。チャネル間にずれがある |
| レートの上限 | ライン数で変わることがある | **全チャネルの合計**で決まることが多い（1 本 48 kHz なら取れても 2 本では超える） |
| 値の意味 | 0 / 1 | ADC の生の値。電圧への換算は宣言（基準電圧、減衰、較正）から host が行う |

ADC の連続変換（DMA）の範囲。ESP32 系は soc_caps の値、RP2 と CH32 はデータシートの目安で、どれも実測ではない。

| 実装 | 合計のサンプルレート | 分解能 | 備考 |
|---|---|---|---|
| ESP32-P4 / S3 | 611 Hz〜83.3 kHz | 12 ビット | 48 kHz は 1 本まで |
| classic ESP32 | 20 kHz〜2 MHz | 9〜12 ビット | DMA は ADC1 のみ |
| RP2040 / RP2350 | 最大 500 kHz | 12 ビット | 1 個の ADC を順番に切り替える |
| CH32（V003 / X035 など） | 数百 kHz〜1 MHz 級 | 10〜12 ビット | target 側のマイコン。probe として使う場合 |

- **チャネルごとのずれを宣言する。** 順番に切り替える実装では、チャネル k のサンプルは先頭から `k × 変換時間`
  遅れる。host がタイミングを比べるときに補正する。同時サンプリングの実装（ADC を 2 個使うなど）は 0。
- **値は生のまま送る。** 較正（ESP32 の eFuse の係数など）は probe によって形が違う。probe は換算の手がかりとして、
  基準電圧（mV）、減衰の設定、較正の有無と、換算に使える形（2 点の値など）を describe で出し、換算は host がする。
  測れる電圧の範囲も宣言する。
- 減衰（ESP32 の 0 / 2.5 / 6 / 11 dB）はチャネルごとの設定として configure で指定する。
- **トリガ**は、ロジックのエッジの代わりにしきい値（ある値を上に / 下に横切る）。ハードウェアで持つ実装は少ない
  （ESP32 の ADC にはモニタ機能があるが、使えるかは未確認）ので、任意にする。
- ロジックとアナログを同じ時間軸でそろえて取る（ミックスドシグナル）のは、実装によっては共通のトリガや開始時刻で
  できる見込みだが、最初は持たない。それぞれの区画の開始時刻（µs）で並べる。

## 3. データの形

- 1 サンプル = 詰めたビット幅 w（1/2/4/8/16）。ライン k がサンプルの k ビット目。
- バイトの中は LSB が先（サンプル i は、バイト `i*w/8` のビット `(i*w)%8` から始まる）。
- 使わないビット（3 本を 4 ビットに詰めたときの 4 本目）は 0。

アナログ:

- 1 値 = 16 ビット（little endian）、右詰め。上位の使わないビットは 0。
- 1 サンプル = 有効なチャネルを番号順に並べたもの（2 本なら ch_a、ch_b、ch_a、ch_b……）。
- 実装が 16 ビットに詰めて送れない形（ESP32 の DMA はチャネル番号付きの 4 バイト）で取る場合は、probe が詰め直す。
  詰め直せないなら、そのぶん転送量が増えることを宣言する。

## 4. 区画と印

リピートとストリーミングは、ともに**位置の付いたバイトの並び**として見せる（[コンソールのストリーム](console-stream.ja.md)
と同じ考え方）。ワンショットは区画が 1 個だけのもの。

```text
segment : serial(u32), position(u32), samples(u32), start_us(u32), trigger_index(u32), flags(u8)
```

| フィールド | 意味 |
|---|---|
| serial | 取得開始からの区画の通し番号 |
| position | 区画の先頭のバイト位置（取得開始から通し、一周したら 0 に戻る） |
| samples | 区画のサンプル数（止めたときの最後の区画は短いことがある） |
| start_us | 区画の最初のサンプルの時刻（probe の起動からの µs、一周を考慮して比べる） |
| trigger_index | 区画の中でトリガが立ったサンプルの番号（プリトリガなしなら 0） |
| flags | bit0 待った（空き区画がなく、前の区画との間が再開時間より長い）、bit1 押し出された（ストリーミング）、bit2 短い |

- ストリーミングでは、区画は probe の都合の区切り（DMA の 1 回ぶんなど）。区画の間が詰まっていれば連続、
  空いていれば取れなかった時間。
- 区画の情報は本文とは別の小さなリングにためる。

## 5. OEP への落とし込み（`oep.fixture.capture` / `oep.fixture.analog`）

ロジックとアナログは別のインターフェースにし、**操作の番号と形はそろえる**。host のコードは取得とポーリングを
共有でき、違うのは configure の中身と describe の宣言だけになる。ADC に使えるピンは限られるので、plan の割り当ても
別にしておく方が扱いやすい。

### 5.1 ライン

ラインは plan で割り当てる（今と同じ。役割 k = ライン k）。ライン数は割り当てた本数、詰めたビット幅は probe が決める。

### 5.2 操作

| op | 名前 | 要求 | 応答 | ロック |
|---:|---|---|---|---|
| 0x01 | configure | mode(u8)、flags(u8: bit0 問い合わせのみ)、rate_hz(u32)、samples(u32)、segments(u16)、pretrigger(u32)、trigger（TLV、任意） | rate_num(u32)、rate_den(u32)、samples(u32)、segments(u16)、width(u8)、jitter(u8)、blocking_ms(u32) | 必要（問い合わせのみなら不要） |
| 0x02 | start | — | blocking_ms(u32)（0 = 取っている間も答える） | 必要 |
| 0x03 | stop | — | — | 必要 |
| 0x04 | status | — | state(u8)、serial_done(u32)、write_pos(u32)、flags(u8) | 不要 |
| 0x05 | read | position(u32)、max(u32) | position(u32)、flags(u8: more、gap)、data | 不要 |
| 0x06 | segments | from_serial(u32) | 区画の情報の並び（§4） | 不要 |
| 0x07 | ack | position(u32) | —（リピートのみ。ここより前の区画を再利用してよい） | 必要 |

- mode: 1 ワンショット、2 リピート、3 ストリーミング。持たない mode は rejected unsupported。
- samples は 1 区画のサンプル数。ストリーミングでは probe が決める（0 を送る）。
- segments はリピートの区画の数（0 = probe に任せる）。
- blocking_ms は、取っている間 probe が答えない時間の見込み。0 なら答える。configure でも start でも返す
  （configure の値は見積もり、start の値は実際）。
- read の max は u32 にする。HS で 1 回 16 KiB 以上読みたいので、u16 では足りない。
- read で要求した位置がもう押し出されていれば、応答の position が先に進み、flags の gap が立つ。
- state: 0 未設定、1 設定済み、2 取得中、3 完了（ワンショット）、4 待機中（リピートで空きなし）、5 エラー。

### 5.3 describe で宣言するもの

| 宣言 | 値 | 目的 |
|---|---|---|
| modes | ビット（1 ワンショット、2 リピート、3 ストリーミング） | どのモードを持つか |
| background | u8（1 = 取っている間も答える） | ワンショットのフラグ |
| rate_min / rate_max | u32 Hz | UI の範囲の目安。**この間が全部設定できるとは限らない**（問い合わせで確かめる） |
| rate_steps | u8（0 ほぼ任意、1 源 ÷ 整数、2 列挙） | 刻みの性質 |
| widths | ビット（1/2/4/8/16） | 詰めたビット幅の候補 |
| max_samples | u32（w = 1 のとき） | ワンショットの上限 |
| segment_max / segment_count | u32 / u16 | リピートの区画の上限 |
| ring_bytes | u32 | ストリーミングのリング |
| rearm_us | u32 | 区画の間に止まる時間の目安 |
| triggers | ビット（即時、レベル、エッジ、パターン、プリトリガ） | 持つトリガ |
| max_read | u32 | 1 回の read で返せる最大長 |

### 5.4 アナログ（`oep.fixture.analog`）で違うところ

- チャネルは plan で割り当てる（役割 k = チャネル k）。ADC のチャネルを持たないピンは plan の段階で拒否する。
- configure に、チャネルごとの減衰（u8 の並び）を足す。rate_hz は**チャネルあたり**のレートとし、合計が上限を
  超えれば拒否する。応答の width は値のビット数（12 など）。
- configure の応答に、チャネル間のずれ（ns、u32）を足す。
- describe に、基準電圧（mV）、減衰の候補、測れる電圧の範囲、較正の形、合計レートの上限、同時サンプリングか
  どうかを足す。
- トリガはしきい値（チャネル、値、上向き / 下向き）。

### 5.5 使い方の例

```text
ワンショット（P4、20 MHz、2 本）
  plan_apply(capture: line0 = GPIO4, line1 = GPIO5)
  configure(mode=1, rate=20 MHz, samples=200000)  → rate 20000000/1, width 2, blocking 0
  start                                           → blocking 0
  status をポーリング（state = 3 まで）。その間も他の操作ができる
  read(0, 16384) を 4 本同時に出して最後まで読む

リピート（I2C のトランザクションを 1 本ずつ）
  configure(mode=2, rate=4 MHz, samples=8192, segments=16, trigger=SCL 立ち下がり)
  start
  segments(from) で終わった区画を知る → read で読む → ack(読み終えた位置)
  ack が遅れると state = 4 になり、次の区画の flags bit0 が立つ

ストリーミング（USB-Serial/JTAG で 1 本 5 MHz = 625 KiB/s）
  configure(mode=3, rate=5 MHz)
  start
  read(pos, max) を同時に複数出して追いかける。gap が立てば、その分は押し出された

アナログのストリーミング（音声 1 ch、48 kHz × 16 ビット = 96 KB/s）
  plan_apply(analog: ch0 = GPIO16)
  configure(mode=3, rate=48000, atten=[11 dB])  → rate 48000/1, width 12, skew 0
  start → read で追いかける。USB-Serial/JTAG（810 KiB/s）で余裕、UART 115200（11 KiB/s）では続かない
```

## 6. 実装ごとの見込み

| 実装 | ワンショット | background | リピート | ストリーミング |
|---|---|---|---|---|
| P4 PARLIO | 1 回 65,408 バイトまで（ドライバの上限） | あり | 区画 64 KiB ずつ。受信を積むと区画の間で数サンプル欠ける（§7.3）→ 区画の間は連続を約束しないので使える | 64 KiB の受信を積み続ける形なら可能。区画の間の欠けは印で示す。partial_rx のリングは途切れ方が不規則なので使わない |
| classic ESP32 sampler | バッファの大きさまで | **なし**（割り込みを止める） | 持たない | 持たない |
| RP2 PIO + DMA（未実装） | 可能 | あり | DMA の連鎖で区画の間も途切れない見込み | リングで可能な見込み |

## 7. 根拠の実測（2026-09-25）

### 7.1 P4 PARLIO のレート（80f1、arduino-esp32 3.3.12）

- 分周レジスタを読むと、ドライバは分数分周を使う。範囲内なら PLL 160 MHz 源でも XTAL 40 MHz 源でも要求どおり
  （33 MHz → 4+28/33、7 MHz → 22+6/7）。
- 範囲は源から源 ÷ 256 まで。PLL 源の 625 kHz（ちょうど 256）は失敗した。
- **範囲外はエラー 0 のまま分周 1（源クロック）で取る。** XTAL 源で 100 kHz / 60 MHz を要求すると 40 MHz で
  取っていた（1 MHz の矩形波を同じピンでループバックして確認）。
- RC_FAST 源は較正値を使い、要求から +5.2%。取ったデータにも揺れが見えた。
- 幅 1/2/4/8/16 はどれも 160 MHz まで設定を受け付ける（実際に取れるかは未確認）。

### 7.2 転送（ポーリングの損）

HS vendor bulk（P4 80f1、EspUsbDevice 2.5.1 buffered、usbip / WSL、ハブ経由）。{位置, 長さ} の要求に長さぶん返す
scratch のファームで、1 本の巨大な要求（= ストリーム）と、多数の要求（= ポーリング）を比べた。

| 応答 | 読みの URB 1 本 | 4 本 | 8 本 |
|---:|---|---|---|
| 1 KiB | 4.4 / 4.1 MB/s | 11.6 / 13.0 | 15.8 / 13.6 |
| 4 KiB | 12.3 / 11.3 | 33.0 / 33.4 | 34.7 / 33.9 |
| 16 KiB | 19.2 / 20.8 | 34.8 / 34.1 | 34.8 / 34.0 |
| 64 KiB | 26.2 / 26.8 | 34.7 / 34.5 | 34.8 / 34.7 |

（ストリーム / ポーリング。ポーリングは同時に出す要求の本数を変えた中の最良。全条件で化け 0）

- host が読みの URB を 4 本以上出し、応答が 16 KiB 以上なら、ポーリングはストリームと 2% 以内。
- 遅くなる原因は、URB を 1 本ずつしか出さないこと（usbip で URB あたり約 0.3 ms）と、応答の小ささ。
- USB-Serial/JTAG（FS）では、1 KiB を 2 本以上同時に出して生の 855 KiB/s の 95%（811 KiB/s）。

### 7.3 64 KiB を超える取り方（P4）

1 MHz の矩形波を 20 MHz、1 本で取り、ランの長さが 10 以外になる場所を数えた。

- 1 回の受信（65,408 バイト、内部 SRAM / PSRAM とも）: 途切れなし。
- 65,408 バイトの受信を 2 / 4 / 16 個積む: 区画の境界ごとに 1 か所ずつ途切れる（数サンプル。周期信号なので
  1 µs の端数としてしか分からない）。
- partial_rx（128 KiB のリング、eof 16 KiB）: 約 7 か所で途切れ、位置は不規則。コールバックの回数も eof と合わない。
- 8 MiB を 1 回で受信しようとすると、ドライバの中でスタック保護フォールトになって落ちる。
