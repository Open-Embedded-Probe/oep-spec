# バスの試験と probe の機能

状態: **ガイド**（規範ではない）。DUT の SPI と I2C の周辺（MCU のコアのドライバ）を probe で試すときに、どの試験をどの機能で
判定できるか、どの試験に標準に無い機能が要るかを整理する。

ライブラリの試験は、デバイスの模型を相手にホストで行う。この文書が扱うのは、probe が相手になる、コアの周辺の試験である。
試験は、何を送り、何が返り、何を見るかを先に決める。probe はその場で応答を考えず、前もって置いたとおりに振る舞う。

## 1. 判定と相手

試験を、判定と相手に分けて考える。

- **判定**: 線の上で起きたことを、ロジックの取り込み（キャプチャ §1.1）と、その解析（wireskein など）で見る。DUT が受けた値は DUT が報告する。
  ロジックの取り込みは聞くだけなので、ほかの機能のピンと共有できる（キャプチャのピンの共有、core §8.1）。相手と同時に使える。
- **相手**: DUT の要求に答える側。DUT が主のときは target（fixture §3、§4）、DUT が従のときは controller（fixture §5、§6）が相手になる。
  故障を起こすのも相手の役である。

判定が取り込みで済み、相手が要らないか標準の相手で足りる試験は、標準の機能だけで行える。相手に標準に無い振る舞いが要る試験は、
その機能が無ければ行えない。

- SPI の主は相手がいなくても線を動かす。主が出す側の試験は、取り込みだけで判定できる。
- I2C の主は、アドレスに ACK が返らないとデータを出さない。データの試験には、ACK を返す相手（i2c-target）が要る。
  判定は取り込みでよい（主が読み出しの各バイトに返した ACK / NACK も、取り込みで見える）。

## 2. 相手の機能

| 機能 | 内容 | 標準 |
|---|---|---|
| 応答 | 前もって置いた応答を返す（SPI は MISO、I2C は読み出しのデータ） | あり（i2c-target の preload_tx は置き場の列、spi-target の arm は 1 回の転送ずつ） |
| 受けたものの記録 | 受けたバイト、ビット数、時刻 | あり（read_rx） |
| 応答の列（SPI） | 続けざまの転送に、転送ごとに違う応答を前もって並べる | 無し |
| 長い転送 | 数 KB の転送を、相手として受け、答える | 形はある（max_length は probe が宣言する） |
| ストレッチ | すべてのバイトで同じ時間、SCL を伸ばす | あり（i2c-target の任意の op） |
| ストレッチの指定 | どのバイトで、どれだけ伸ばすか | 無し |
| NACK | アドレスに k 回 NACK を返す、データの n バイト目に NACK を返す | 無し |
| 線の保持 | SDA や SCL を low に保ち、host が離す | あり（gpio のオープンドレイン） |
| クロックを数えて離す | SDA を low に保ち、SCL が k 回来たら離す（固まった従の真似） | 無し |
| バスを持つ | 先に START を出し、STOP を出さずにバスを持つ | あり（i2c-controller の held） |
| 時間を指定して送る（SPI） | CS からクロック、クロックから CS、転送の間の時間 | あり（spi-controller の gap_ns、setup_ns、hold_ns） |
| 時間を指定して送る（I2C） | セットアップ、ホールド、tBUF などを指定する | 無し（クロックの周波数だけ） |
| 途中で切る | バイトの途中で転送をやめる、途中で START や STOP を出す | 無し |
| 拡張したアドレス | 10 ビットのアドレス、general call、複数のアドレスに答える | 無し（i2c-target は予約されたアドレスを断る） |
| 3 線式 | データの線 1 本を、向きを切り替えて使う | 無し |
| 複数の相手 | 1 本の SPI のバスに、CS の違う相手を複数置く | 無し |
| 周波数 | 取り込みより速いクロックの周波数 | あり（counter） |
| 電圧 | 立ち上がりの時間、ぶつかり合い、level | アナログの取り込み（帯域の内だけ） |

## 3. SPI、DUT が主

| 試験 | 判定 | 相手 |
|---|---|---|
| mode（CPOL と CPHA） | 取り込み: CS が有効になる前の SCK の level と、MOSI が変わるエッジ | 不要 |
| mode を変えたときの SCK | 取り込み: CS が有効になる前に、SCK が新しい level に落ち着いているか | 不要 |
| MOSI の値、ビット順、16 / 32 ビットの語のバイトの順 | 取り込み | 不要 |
| クロックの周波数（最低と最高） | 取り込み。取り込みより速いものは counter | 不要 |
| CS の時間、ハードウェアの CS（語ごとのパルスを含む） | 取り込み | 不要 |
| 長い転送、DMA の転送の隙間 | 取り込み | 不要 |
| 受信だけのモードのクロック数 | 取り込み | 不要 |
| MISO の受け取り（mode、ビット順ごと） | DUT が受けた値 | 応答（標準） |
| 誤った CRC を見つけるか | DUT の判定 | 応答（標準。CRC もバイトとして置く） |
| 続けざまの転送の MISO | DUT が受けた値 | 応答の列（無し） |
| 長い転送の MISO | DUT が受けた値 | 長い転送（probe の宣言による） |
| 3 線式 | 取り込み、DUT が受けた値 | 3 線式（無し） |
| 共有バスで複数のデバイス | 取り込み、DUT が受けた値 | 複数の相手（無し） |
| MISO を取り込む時点の余裕 | DUT が受けた値 | MISO を ns 単位で遅らせる（§7） |

相手が受けたデータでは、mode 0 と 3、mode 1 と 2 を区別できない（データを取り込むエッジが同じ）。mode は取り込みで判定する。

## 4. SPI、DUT が従

| 試験 | 判定 | 相手 |
|---|---|---|
| DUT が受けた値、mode、ビット順 | DUT が受けた値 | 時間を指定して送る（標準） |
| DUT が出す MISO の値 | 相手の記録 | 標準 |
| DUT が出す MISO のエッジ | 取り込み | 標準 |
| CS から最初のビットまでの準備時間の下限 | 相手の記録 | 標準（setup_ns を変えていく） |
| 転送の間の最小の時間、オーバーランの検出 | 相手の記録、DUT の報告 | 標準（gap_ns を変えていく） |
| DUT が受けられる最高のクロック | 相手の記録 | 標準（probe の max_clock_hz まで） |
| CS が無効な間に MISO を離しているか | 取り込み、電圧 | MISO に弱いプルをかける（無し: controller の MISO はプルの無い入力） |
| CS をバイトの途中で切る | DUT の報告 | 途中で切る（無し） |
| 3 線式 | DUT が受けた値、相手の記録 | 3 線式（無し） |

## 5. I2C、DUT が主

| 試験 | 判定 | 相手 |
|---|---|---|
| アドレスのバイト、相手が居ないときの扱い（戻り値と STOP） | 取り込み、DUT の戻り値 | 不要 |
| 時間（tLOW、tHIGH、tSU;STA、tHD;STA、tSU;DAT、tHD;DAT、tSU;STO、tBUF）と周波数 | 取り込み | ACK を返す相手（標準） |
| 書き込み、読み出し、repeated START と STOP の別 | 取り込み、相手の記録 | 応答（標準） |
| 読み出しの最後のバイトへの NACK | 取り込み | 応答（標準） |
| ストレッチを待つ | 取り込み | ストレッチ（標準） |
| ストレッチがタイムアウトを超える | DUT の戻り値と、次の転送 | ストレッチ（max_stretch_us の内）か線の保持（標準） |
| SCL が固まる、SMBus のタイムアウト | DUT の戻り値、取り込み | 線の保持（標準） |
| ほかの主がバスを使っている間に始めないか | 取り込み | バスを持つ（標準） |
| SDA が固まったときに、クロックを出して STOP を出すか | 取り込み | 線の保持（標準） |
| SDA が固まったところから、回復できるか | DUT の戻り値、取り込み | クロックを数えて離す（無し） |
| SMBus の PEC | DUT の判定 | 応答（標準。PEC もバイトとして置く） |
| データの n バイト目の NACK | DUT の戻り値、取り込み | NACK（無し） |
| ACK のポーリング（書き込み中の EEPROM） | DUT の戻り値、取り込み | NACK（k 回、無し） |
| 特定のバイトでだけ伸ばす | 取り込み | ストレッチの指定（無し） |
| 10 ビットのアドレス、general call | 取り込み、相手の記録 | 拡張したアドレス（無し） |
| 調停、途中の START や STOP（バスのエラー） | DUT の戻り値、取り込み | DUT のクロックに合わせた注入（§7） |
| グリッチフィルタ | DUT が受けた値 | ns 単位のパルス（§7） |
| 立ち上がりの時間、オープンドレインを守っているか | 電圧 | 不要（§7） |

## 6. I2C、DUT が従

| 試験 | 判定 | 相手 |
|---|---|---|
| 受信、応答、書いてから repeated START で読む順、DUT が持つより多く読まれたとき | 相手の結果、DUT の報告 | 標準 |
| DUT のストレッチの長さ | 取り込み | 標準 |
| アドレスが合わないときの NACK、general call | 相手の結果 | 標準（予約されたアドレスも送れる） |
| DUT が受けられる最高のクロック | 相手の結果 | 標準（probe の max_clock_hz まで） |
| 規格の下限の時間で送っても受けられるか | 相手の結果、取り込み | I2C の時間の指定（無し） |
| 主がバイトの途中で消える、途中で START を出す | DUT の報告、次の転送 | 途中で切る（無し） |
| 10 ビットのアドレス、複数のアドレス | 相手の結果 | 拡張したアドレス（無し） |

DUT が従の試験では probe がクロックを出すので、途中で切ることや時間の指定は、probe 自身の時間で行える。

## 7. 原理的に難しいもの

probe の作り方によらず難しいもの。

1. **DUT のクロックに合わせた注入**（調停の競り合い、途中の START や STOP、決まったビットのグリッチ）。
   - 1 ビットのうちに反応する必要がある（1 MHz の I2C で 100 ns 以下）。
   - ソフトウェアでは間に合わず、ハードウェアで時間を決めて動く仕組みが要る。
2. **ns 単位の余裕**（MISO を取り込む時点、高速の SPI のセットアップとホールド、50 ns 以下のスパイクを無視するグリッチフィルタ）。
   - 出す側と測る側の両方に、数 ns の分解能が要る。
3. **電気的なこと**（立ち上がりの時間、ぶつかり合い、level）。
   - アナログの取り込みの帯域の内だけで、高速のバスには足りない。
4. **その場で答えるもの**（QSPI のメモリマップ、SD のファイル操作）。
   - 読む場所を CPU や上の層が決めるので、前もって置けない。本物の部品を相手にする。
5. **1 本のバスの MISO を、複数の相手で本当に共有すること。**

## 8. 標準に無い機能と、それで行える試験

試験に効く順に並べる。

| 機能 | 行える試験 |
|---|---|
| NACK（アドレスに k 回、n バイト目） | I2C の主の誤りの扱いの大半（データの NACK、ACK のポーリング） |
| 応答の列（SPI） | 続けざまの転送の MISO |
| ストレッチの指定、クロックを数えて離す | 特定のバイトでの待ち、固まったバスからの回復 |
| I2C の時間の指定、途中で切る | DUT が従のときの、規格の下限と、途中で切られた転送 |
| MISO に弱いプルをかける | DUT が従のときの、MISO を離しているかの確認 |
| 拡張したアドレス、3 線式、複数の相手 | 10 ビットのアドレス、general call、半二重、共有バス |
| DUT のクロックに合わせた注入 | 調停、バスのエラー（§7 の 1） |
