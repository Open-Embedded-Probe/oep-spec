# 周辺の試験の層と probe の機能

状態: **ガイド**（規範ではない）。MCU の周辺とそれを使うソフトウェアの試験を、どの層で行うかに分け、OEP の probe が受け持つ層で、
どの試験をどの機能で行えるか、どの試験に標準に無い機能が要るかを整理する。

## 1. 層

試すものの境界の外側に、用途に合わせたスタブ（相手の代わり）か計測器を置く。境界をどこで切るかで層が決まる。内側から順に並べる。

| 層 | 境界 | 相手と判定 | 例 |
|---|---|---|---|
| 1 論理 | 試すコードを、ハードウェア無しで動かす | 相手はソフトウェアのスタブ。判定は、スタブが受けた呼び出しの記録 | ライブラリをデバイスの模型と動かす。コアの計算（分周、タイミングのレジスタ値、ピンの割り当て）をホストで確かめる。OEP の host を仮想の probe と動かす |
| 2 DUT の中 | 実機の上で、ピンに出ない機能 | 相手は要らない。DUT 自身の検査と、デバッグの線で読む DUT の中 | DMA、割り込み、flash、CRC、暗号、乱数 |
| 3 観測 | 物理的な IF の上 | 聞くだけの計測器。信号の時間、周波数、プロトコルとして破綻していないか | ロジックアナライザとその解析（OEP の取り込みと wireskein）、オシロスコープ、周波数カウンタ |
| 4 汎用の相手 | 物理的な IF の先 | 汎用の装置が、刺激と相手（線の上のスタブ）になる。治具の回路の切り替えもここ | OEP の probe の fixture |
| 5 専用の相手 | 物理的な IF の先 | その周辺の専用のハード（コントローラ、トランシーバ、PHY）と、相手のプロトコルのスタックを持つ装置 | USB のコントローラを積んだボード、CAN の節、PC、PD のテスタ |
| 6 実物 | 物理的な IF の先 | 本物の部品と機器 | センサ、SD カード、LCD、充電器 |

- **試せるいちばん内側の層で試す。** 外の層では、内側で確かめられないこと（信号、時間、本物とのつながり）だけを確かめる。
- **スタブは用途ごとに立てる。** 試すものが変われば、同じ境界にも別のスタブを立てる。スタブと計測器は、それぞれの実装の試験で
  確かめる（模型の準拠の試験、probe の適合の試験）。
- **層 6 を減らす。** 実物の振る舞いを記録して、層 1 のスタブと層 4 の相手の中身にする。層 6 に残すのは、代表の部品とのつながりの確認と、
  層 5 までで作れないものだけにする。
- **記録を取るのは試験の前の準備で、試験ではない。** 層 5 や層 6 で一度取り、解析して、スタブの中身や振る舞いにする
  （応答の値、応答までの時間、SD のイメージ）。
- **層 4 と層 5 の境**: 層 4 は、汎用の装置が線の単位で作れる相手。層 5 は、専用の周辺や物理層、相手のプロトコルのスタックが要る相手。
  専用の周辺を積んだ probe が、自分の名前の拡張（core §12）で層 5 の相手になってもよいが、標準の汎用の機能とは分ける。

### 2.1 検査する側の部品

同じ周辺は、検査する側（probe）では、層 3 と層 4 の機能を作る部品になる。probe の作り手は、チップが持つ周辺から次のように選ぶ。

| OEP の機能 | 作る部品の例 |
|---|---|
| ロジックの取り込み | 並列の入力（PARLIO の受け、LCD とカメラの周辺のカメラのモード、I2S の並列のモード）、PIO、GPIO を読む割り込み |
| エッジの数と周波数 | パルスの計数（PCNT、PWM のスライスの数える入力）、タイマの外部クロック |
| アナログの取り込み | ADC と DMA |
| PWM の出力 | LED 用の PWM、モータ制御の PWM（位相、相補、デッドタイム）、タイマ |
| パターンの出力 | RMT の送り、PARLIO の送り、I2S や LCD の並列の出力、PIO、HSTX |
| アナログの出力 | DAC。無いチップは、PWM と RC のフィルタか、外付けの DAC を治具にする |
| UART、I2C、SPI の相手 | ハードウェアの周辺、PIO |
| 答える相手 | PIO（バイトやビットの単位で反応できる）、送るデータを先読みしない SPI の従 |
| 専用の相手（層 5） | USB OTG、CAN のコントローラとトランシーバ、無線、Ethernet の MAC |

## 3. OEP が受け持つ層

OEP の probe は、層 3 の観測と、層 4 の汎用の相手を受け持つ。層 2 では、デバッグの線から DUT の中を読む（`oep.target.riscv-dm`、
`oep.target.arm-adi`）。

- **層 3**: ロジックの取り込み（`oep.fixture.logic`）、アナログの取り込み（`oep.fixture.analog`）、エッジの数と周波数（`oep.fixture.counter`）。
  ロジックの取り込みとエッジの数は、聞くだけなので、ほかの機能のピンと共有できる（キャプチャのピンの共有、core §8.1）。
  層 4 の相手と同時に使える。プロトコルを読むのは解析器（wireskein など）の役で、取り込みはどのプロトコルにも同じである。
- **層 4**: 下の標準のインターフェースが刺激と相手になる。試験は、何を出し、何が返るかを先に決める。

### 3.1 標準の刺激と相手

| インターフェース | 刺激または相手としてできること | できないこと |
|---|---|---|
| `oep.fixture.gpio` | level、プル、オープンドレインを出す。DUT のピンを読む | 時間を決めて出す（1 回の要求の中の順は守るが、間の時間は決まらない） |
| `oep.fixture.pwm` | 周波数とデューティを決めた方形波を、出し続ける | 出力どうしの位相、決まった数のパルス、単発のパルス |
| `oep.fixture.dac` | アナログの値を置く | 時間で変える波形 |
| `oep.fixture.uart` | baud（要求から ±5% の内）と format（データ長、パリティ、ストップビット）を決めて送受信する | break、9 ビット、1 本の線での半二重、フロー制御の線 |
| `oep.fixture.i2c-target`、`oep.fixture.spi-target` | DUT が主のときの相手。前もって置いた応答、受けたものの記録、すべてのバイトで同じストレッチ | §7、§8 の「無し」 |
| `oep.fixture.i2c-controller`、`oep.fixture.spi-controller` | DUT が従のときの相手。SPI は CS の時間を指定して送る | §7、§8 の「無し」 |
| `oep.fixture.capture-group` | 出来事の元を持つ probe は、出来事でパルスを 1 つ出す（trigger_out） | パルスの後の列 |

### 3.2 標準に無い機能

層 4 の試験に要るが、標準に無いもの。周辺をまたいで効く範囲の広い順に並べる。

| 機能 | 内容 | 主に効く周辺 |
|---|---|---|
| パターンの出力 | 複数のピンに、時間を決めた level の列を出す。繰り返し、出来事で始めることもできる | IR の受信、エンコーダ、決まった数のパルス、単発のパルス幅、チャタリング、UART の break、LIN、割り込みの連打 |
| I2C の NACK とストレッチの指定 | アドレスに k 回 NACK、n バイト目に NACK、どのバイトでどれだけ伸ばすか、SDA を引いて SCL が k 回来たら離す | I2C |
| SPI の応答の列 | 続けざまの転送に、転送ごとに違う応答を前もって並べる | SPI |
| アナログの波形 | DAC の値を時間で変える（列、繰り返し） | ADC の連続の変換、DMA、比較器の応答 |
| 答える相手 | DUT の線に合わせ、受けたものに応じて、DUT が待つ時間のうちに答える（§3.3） | SD、SPI flash、FSMC、1-Wire、I2S、I2C の調停とバスのエラー |
| 電源 | DUT の電源を入れる、切る、電圧を変える。電流を測る | 起動、低電圧の検出、低電力のモード、書き込み中の電源断 |
| 主の拡張 | I2C で時間を指定して送る、途中で切る。SPI で途中で切る、MISO に弱いプルをかける | I2C、SPI の従 |
| アドレスと線の拡張 | 10 ビットのアドレス、general call、3 線式の SPI、1 本の SPI のバスに複数の相手 | I2C、SPI |
| 速いパターンの出力 | クロックとデータの線に、速いデータを出し続ける | DVP、RGB の LCD の入力側 |

### 3.3 答える相手の時間

受けたものに応じて答える相手は、DUT が待つ時間のうちに、相手が答えを用意できるかで決まる。答える中身（SD のイメージ、flash の中身）は
前もって持っておく。待ちが長いものは、中身を host から取り寄せてもよい。

| 相手 | DUT が待つ時間 |
|---|---|
| SD カード（SPI のモード） | コマンドの応答は 0〜8 バイトのうち（NCR）。読み出しのデータは、データの印（0xFE）の前に 0xFF を返して、読み出しの時間の上限まで待たせられる。書き込みの後は busy（0x00）を返して待たせられる |
| SD カード（SD のバスのモード） | コマンドの応答は 2〜64 クロックのうち。データは SPI のモードと同じく待たせられる。CRC をその場で付ける |
| SPI flash | ID、ステータスは前もって置ける。待ちの無い読み出しは、アドレスの最後のビットの次のビットから。fast read はダミーのクロックのぶん |
| QSPI のメモリマップ | ダミーのクロック（DUT の設定による） |
| FSMC / FMC の非同期の SRAM | データの期間（DUT の設定による） |
| 1-Wire の従 | 主が線を下げてから、主が読むまで（約 15 µs） |
| I2S の相手 | BCLK の 1 ビット |
| I2C の調停、途中の START や STOP | ビットの中（1 MHz で 100 ns 以下） |

待つ時間がビットやバイトの単位のものは、ソフトウェアでは間に合わないことが多く、ハードウェアで時間を決めて動く仕組みが要る。
DUT の設定で待ちを長くできるもの（ダミーのクロック、データの期間、遅いクロック）は、その設定で試せる範囲が広がる。

## 4. 周辺ごとの試験（層 3 と層 4）

以下の表の「層」は、3（観測だけ）、4（汎用の相手。標準のインターフェースか、§3.2 の標準に無い機能）、5、6、難（§15）のどれかである。

## 5. GPIO と外部割り込み

| 試験 | 判定 | 層 |
|---|---|---|
| 出力の level、モード（プッシュプル、オープンドレイン） | 取り込み、gpio で読む | 3（オープンドレインは 4: gpio のプルアップ） |
| 入力を読む、プル | DUT の報告 | 4: gpio |
| 出力を切り替える速さ | 取り込み | 3 |
| 割り込みのエッジの種類と遅れ | 取り込み（刺激のエッジと、DUT が返すピンの間） | 4: pwm か gpio |
| 速い割り込みの取りこぼし | DUT の数えた数と、counter | 4: pwm。決まった数はパターンの出力（無し） |
| チャタリングの除去 | DUT の報告 | 4: パターンの出力（無し） |
| 出力の強さ、スルーレート、入力の耐圧 | 電圧 | 難 |

## 6. 時間、クロック、リセット、電源

| 試験 | 判定 | 層 |
|---|---|---|
| millis、micros、delay の精度 | 取り込み、counter（DUT がピンを切り替える） | 3 |
| クロックの出力（MCO）、RTC の周波数 | counter | 3 |
| 外部のクロックで動く、外部のクロックが止まったときの切り替え | DUT の報告、取り込み | 4: pwm（DUT のクロックとして出し、止める） |
| リセットのピン、リセットの理由 | DUT の報告、デバッグの線 | 4: gpio |
| ウォッチドッグの時間 | 取り込み（DUT のピンが止まってから再起動まで） | 3 |
| ピンでのスリープからの復帰と、その遅れ | 取り込み | 4: gpio か pwm |
| 電源の入れ方による起動、低電圧の検出、書き込み中の電源断 | DUT の報告、取り込み | 4: 電源（無し） |
| 低電力のモードの電流 | 電流 | 4: 電源（無し） |

時間の判定は probe の時計が基準になるので、その精度より細かい誤差は判定できない。

## 7. I2C

DUT が主のとき、相手は i2c-target である。I2C の主は、アドレスに ACK が返らないとデータを出さないので、データの観測にも ACK を返す
相手が要る。判定は取り込みでよい（主が読み出しの各バイトに返した ACK / NACK も見える）。

| 試験 | 判定 | 層 |
|---|---|---|
| アドレスのバイト、相手がいないときの扱い（戻り値と STOP） | 取り込み、DUT の戻り値 | 3 |
| 時間（tLOW、tHIGH、tSU;STA、tHD;STA、tSU;DAT、tHD;DAT、tSU;STO、tBUF）と周波数 | 取り込み | 3（ACK を返す 4: i2c-target と） |
| 書き込み、読み出し、repeated START と STOP の別、読み出しの最後の NACK | 取り込み、相手の記録 | 4: i2c-target |
| ストレッチを待つ | 取り込み | 4: i2c-target の stretch |
| ストレッチがタイムアウトを超える、SCL が固まる、SMBus のタイムアウト | DUT の戻り値と、次の転送 | 4: stretch か gpio で線を保つ |
| ほかの主がバスを使っている間に始めないか | 取り込み | 4: i2c-controller でバスを持つ |
| SDA が固まったときにクロックと STOP を出すか | 取り込み | 4: gpio で SDA を保つ |
| SDA が固まったところから回復できるか | DUT の戻り値、取り込み | 4: SCL が k 回来たら離す（無し） |
| SMBus の PEC | DUT の判定 | 4: i2c-target（PEC もバイトとして置く） |
| データの n バイト目の NACK、ACK のポーリング | DUT の戻り値、取り込み | 4: NACK（無し） |
| 特定のバイトでだけ伸ばす | 取り込み | 4: ストレッチの指定（無し） |
| 10 ビットのアドレス、general call | 取り込み、相手の記録 | 4: アドレスの拡張（無し） |
| 調停、途中の START や STOP（バスのエラー） | DUT の戻り値 | 4: 答える相手（無し、§3.3） |
| グリッチフィルタ（50 ns 以下のスパイク） | DUT の戻り値 | 難 |
| 立ち上がりの時間、オープンドレインを守っているか | 電圧 | 難 |

DUT が従のときは、i2c-controller が相手になる。probe がクロックを出すので、途中で切ることや時間の指定は probe 自身の時間で行える。

| 試験 | 判定 | 層 |
|---|---|---|
| 受信、応答、書いてから repeated START で読む順、DUT が持つより多く読まれたとき | 相手の結果、DUT の報告 | 4: i2c-controller |
| DUT のストレッチの長さ | 取り込み | 4: i2c-controller |
| アドレスが合わないときの NACK、general call | 相手の結果 | 4: i2c-controller（予約されたアドレスも送れる） |
| DUT が受けられる最高のクロック | 相手の結果 | 4: i2c-controller（probe の max_clock_hz まで） |
| 規格の下限の時間で送っても受けられるか | 相手の結果、取り込み | 4: 時間の指定（無し） |
| 主がバイトの途中で消える、途中で START を出す | DUT の報告、次の転送 | 4: 途中で切る（無し） |
| 10 ビットのアドレス、複数のアドレス | 相手の結果 | 4: アドレスの拡張（無し） |

## 8. SPI

SPI の主は相手がいなくても線を動かすので、主が出す側の試験は層 3 で行える。

| 試験 | 判定 | 層 |
|---|---|---|
| mode（CPOL と CPHA） | 取り込み: CS が有効になる前の SCK の level と、MOSI が変わるエッジ | 3 |
| mode を変えたときの SCK | 取り込み: CS が有効になる前に、SCK が新しい level に落ち着いているか | 3 |
| MOSI の値、ビット順、16 / 32 ビットの語のバイトの順 | 取り込み | 3 |
| クロックの周波数 | 取り込み。取り込みより速いものは counter | 3 |
| CS の時間、ハードウェアの CS（語ごとのパルスを含む）、DMA の転送の隙間、受信だけのモードのクロック数 | 取り込み | 3 |
| MISO の受け取り、誤った CRC を見つけるか | DUT の報告 | 4: spi-target（CRC もバイトとして置く） |
| 長い転送の MISO | DUT の報告 | 4: spi-target（長さは probe の宣言による） |
| 続けざまの転送の MISO | DUT の報告 | 4: 応答の列（無し） |
| SPI flash、QSPI のメモリマップの読み出し | DUT の報告 | 4: 答える相手（無し、§3.3） |
| 3 線式、共有バスで複数のデバイス | 取り込み、DUT の報告 | 4: 線の拡張（無し） |
| MISO を取り込む時点の余裕 | DUT の報告 | 難 |

相手が受けたデータでは、mode 0 と 3、mode 1 と 2 を区別できない（データを取り込むエッジが同じ）。mode は取り込みで判定する。

DUT が従のときは、spi-controller が相手になる。

| 試験 | 判定 | 層 |
|---|---|---|
| DUT が受けた値、出す MISO、mode、ビット順 | 相手の記録、取り込み | 4: spi-controller |
| CS から最初のビットまでの準備時間の下限、転送の間の最小の時間、オーバーラン | 相手の記録、DUT の報告 | 4: spi-controller（setup_ns、gap_ns を変えていく） |
| DUT が受けられる最高のクロック | 相手の記録 | 4: spi-controller（probe の max_clock_hz まで） |
| CS が無効な間に MISO を離しているか | 取り込み、電圧 | 4: MISO に弱いプルをかける（無し） |
| CS をバイトの途中で切る、3 線式 | DUT の報告 | 4: 主の拡張（無し） |

## 14. 専用の相手が要る周辺（層 5）

層 3 で見られる信号はあるが、相手には専用のハードとプロトコルのスタックが要る。

| 周辺 | 層 3 で見られるもの | 層 5 の相手の例 |
|---|---|---|
| CAN、CAN FD | DUT のループバックか聞くだけのモードでの、TX のピンのビットの時間とフレーム | CAN のコントローラとトランシーバを積んだ節 |
| USB（device、host、OTG） | 低速と FS の信号の一部、VBUS と ID の線 | USB のコントローラを積んだボード、PC |
| USB PD、Type-C | CC の波形 | PD のテスタ、PD の電源 |
| Ethernet | RMII の信号 | PC、スイッチ |
| 無線 | — | 相手の無線機 |

LIN と RS-485 は、トランシーバを治具として層 4 の uart につなげば、層 4 で試せる。

## 15. 原理的に難しいもの

どの層の装置を使っても難しいもの。受けたものに応じて答える相手は、DUT が待つ時間しだいで作れるので、ここには入れない（§3.3）。

1. **ns 単位の時間**（SPI の取り込みの余裕、デッドタイム、50 ns 以下のスパイクを無視するフィルタ）。
   - 出す側と測る側の両方に、数 ns の分解能が要る。
2. **電気的なこと**（出力の強さ、スルーレート、立ち上がりの時間、耐圧）。
   - アナログの取り込みの帯域の内だけで測れる。
