# 周辺の試験と probe の機能

状態: **ガイド**（規範ではない）。DUT の周辺（MCU のコアのドライバ）を probe で試すときに、どの試験をどの機能で判定できるか、
どの試験に標準に無い機能が要るか、どの試験が原理的に難しいかを整理する。

ライブラリの試験は、デバイスの模型を相手にホストで行う。この文書が扱うのは、probe が相手になる、コアの周辺の試験である。
試験は、何を出し、何が返り、何を見るかを先に決める。probe はその場で応答を考えず、前もって置いたとおりに振る舞う。

## 1. 判定、刺激、相手

試験に要るものを 3 つに分ける。

- **判定**: 起きたことを見る。
  - ロジックの取り込み（`oep.fixture.logic`）と、その解析（wireskein など）。聞くだけなので、ほかの機能のピンと共有できる（キャプチャのピンの
    共有、core §8.1）。刺激や相手と同時に使える。プロトコルを読むのは解析器の役で、取り込みはどのプロトコルにも同じである。
  - アナログの取り込み（`oep.fixture.analog`）、エッジの数と周波数（`oep.fixture.counter`）。
  - DUT の報告（コンソール）と、デバッグの線から読む DUT の中（`oep.target.riscv-dm`、`oep.target.arm-adi`）。後者は試験のスケッチに
    報告を書かなくても、レジスタやメモリを読める。
- **刺激**: DUT の入力に、DUT の動きと関係なく出すもの。
- **相手**: DUT の要求に答えるもの。故障を起こすのも相手の役である。

DUT が自分で信号を出す試験は、判定だけで行える。刺激や相手が要る試験は、その機能があるときだけ行える。

| 区分 | 意味 |
|---|---|
| 不要 | DUT が自分で出す。判定だけで行える |
| 標準 | 標準のインターフェースで刺激または相手になれる |
| 無し | 標準に無い機能が要る（§3） |
| 難 | 原理的に難しい（§16） |

## 2. 標準の刺激と相手

| インターフェース | 刺激または相手としてできること | できないこと |
|---|---|---|
| `oep.fixture.gpio` | level、プル、オープンドレインを出す。DUT のピンを読む | 時間を決めて出す（1 回の要求の中の順は守るが、間の時間は決まらない） |
| `oep.fixture.pwm` | 周波数とデューティを決めた方形波を、出し続ける | 出力どうしの位相、決まった数のパルス、単発のパルス |
| `oep.fixture.dac` | アナログの値を置く | 時間で変える波形 |
| `oep.fixture.uart` | baud（要求から ±5% の内）と format（データ長、パリティ、ストップビット）を決めて送受信する | break、9 ビット、1 本の線での半二重、フロー制御の線 |
| `oep.fixture.i2c-target`、`oep.fixture.spi-target` | DUT が主のときの相手。前もって置いた応答、受けたものの記録、すべてのバイトで同じストレッチ | §8、§9 の「無し」 |
| `oep.fixture.i2c-controller`、`oep.fixture.spi-controller` | DUT が従のときの相手。SPI は CS の時間を指定して送る | §8、§9 の「無し」 |
| `oep.fixture.capture-group` | 出来事の元を持つ probe は、出来事でパルスを 1 つ出す（trigger_out） | パルスの後の列 |

## 3. 標準に無い機能

周辺をまたいで要るものを、効く範囲の広い順に並べる。

| 機能 | 内容 | 主に効く周辺 |
|---|---|---|
| パターンの出力 | 複数のピンに、時間を決めた level の列を出す。繰り返し、出来事で始めることもできる | IR の受信、エンコーダ、決まった数のパルス、単発のパルス幅、チャタリング、UART の break、LIN、割り込みの連打 |
| I2C の NACK とストレッチの指定 | アドレスに k 回 NACK、n バイト目に NACK、どのバイトでどれだけ伸ばすか、SDA を引いて SCL が k 回来たら離す | I2C |
| SPI の応答の列 | 続けざまの転送に、転送ごとに違う応答を前もって並べる | SPI |
| アナログの波形 | DAC の値を時間で変える（列、繰り返し） | ADC の連続の変換、DMA、比較器の応答 |
| 反応する相手 | DUT の線に合わせ、受けたものに応じて、DUT が待つ時間のうちに答える（§3.1） | SD、SPI flash、1-Wire、I2S、CAN、I2C の調停とバスのエラー |
| 電源 | DUT の電源を入れる、切る、電圧を変える。電流を測る | 起動、低電圧の検出、低電力のモード |
| 主の拡張 | I2C で時間を指定して送る、途中で切る。SPI で途中で切る、MISO に弱いプルをかける | I2C、SPI の従 |
| アドレスと線の拡張 | 10 ビットのアドレス、general call、3 線式の SPI、1 本の SPI のバスに複数の相手 | I2C、SPI |
| 速いパターンの出力 | クロックとデータの線に、速いデータを出し続ける | DVP |

### 3.1 反応する相手の時間

受けたものに応じて答える相手は、原理的に無理なのではない。DUT が待つ時間のうちに、probe が答えを用意できるかで決まる。
答える中身（SD のイメージ、flash の中身）は前もって持っておく。待ちが長いものは、中身を host から取り寄せてもよい。

| 相手 | DUT が待つ時間 |
|---|---|
| SD カード（SPI のモード） | コマンドの応答は 0〜8 バイトのうち（NCR）。読み出しのデータは、データの印（0xFE）の前に 0xFF を返して、読み出しの時間の上限まで待たせられる。書き込みの後は busy（0x00）を返して待たせられる |
| SD カード（SD のバスのモード） | コマンドの応答は 2〜64 クロックのうち。データは SPI のモードと同じく待たせられる。CRC をその場で付ける |
| SPI flash | ID、ステータスは前もって置ける。待ちの無い読み出しは、アドレスの最後のビットの次のビットから。fast read はダミーのクロックのぶん |
| QSPI のメモリマップ | ダミーのクロック（DUT の設定による） |
| FSMC / FMC の非同期の SRAM | データの期間（DUT の設定による） |
| 1-Wire の従 | 主が線を下げてから、主が読むまで（約 15 µs） |
| I2S の相手 | BCLK の 1 ビット |
| CAN の節 | ACK はビット 1 つ。誤りのフレームは誤りを見てから次のビット |
| I2C の調停、途中の START や STOP | ビットの中（1 MHz で 100 ns 以下） |

待つ時間がビットやバイトの単位のものは、ソフトウェアでは間に合わないことが多く、ハードウェアで時間を決めて動く仕組みが要る。
DUT の設定で待ちを長くできるもの（ダミーのクロック、データの期間、遅いクロック）は、その設定で試せる範囲が広がる。

## 4. GPIO と外部割り込み

| 試験 | 判定 | 刺激、相手 |
|---|---|---|
| 出力の level、モード（プッシュプル、オープンドレイン） | 取り込み、gpio で読む | 不要（オープンドレインは gpio のプルアップ、標準） |
| 入力を読む、プル | DUT の報告 | gpio（標準） |
| 出力を切り替える速さ | 取り込み | 不要 |
| 割り込みのエッジの種類と遅れ | 取り込み（刺激のエッジと、DUT が返すピンの間） | pwm か gpio（標準） |
| 速い割り込みの取りこぼし | DUT の数えた数と、counter | pwm（標準）。決まった数はパターンの出力（無し） |
| チャタリングの除去 | DUT の報告 | パターンの出力（無し） |
| 出力の強さ、スルーレート、入力の耐圧 | 電圧 | 難 |

## 5. 時間、クロック、リセット、電源

| 試験 | 判定 | 刺激、相手 |
|---|---|---|
| millis、micros、delay の精度 | 取り込み、counter（DUT がピンを切り替える） | 不要 |
| クロックの出力（MCO）、RTC の周波数 | counter | 不要 |
| 外部のクロックで動く、外部のクロックが止まったときの切り替え | DUT の報告、取り込み | pwm（DUT のクロックとして出し、止める。標準） |
| リセットのピン、リセットの理由 | DUT の報告、デバッグの線 | gpio（標準） |
| ウォッチドッグの時間 | 取り込み（DUT のピンが止まってから再起動まで） | 不要 |
| ピンでのスリープからの復帰と、その遅れ | 取り込み | gpio か pwm（標準） |
| 電源の入れ方による起動、低電圧の検出 | DUT の報告、取り込み | 電源（無し） |
| 低電力のモードの電流 | 電流 | 電源（無し） |

時間の判定は probe の時計が基準になるので、その精度より細かい誤差は判定できない。

## 8. I2C

DUT が主のとき、相手は i2c-target である。I2C の主は、アドレスに ACK が返らないとデータを出さないので、データの試験には ACK を返す
相手が要る。判定は取り込みでよい（主が読み出しの各バイトに返した ACK / NACK も見える）。

| 試験 | 判定 | 刺激、相手 |
|---|---|---|
| アドレスのバイト、相手がいないときの扱い（戻り値と STOP） | 取り込み、DUT の戻り値 | 不要 |
| 時間（tLOW、tHIGH、tSU;STA、tHD;STA、tSU;DAT、tHD;DAT、tSU;STO、tBUF）と周波数 | 取り込み | i2c-target（標準） |
| 書き込み、読み出し、repeated START と STOP の別、読み出しの最後の NACK | 取り込み、相手の記録 | i2c-target（標準） |
| ストレッチを待つ | 取り込み | i2c-target の stretch（標準） |
| ストレッチがタイムアウトを超える、SCL が固まる、SMBus のタイムアウト | DUT の戻り値と、次の転送 | stretch か gpio で線を保つ（標準） |
| ほかの主がバスを使っている間に始めないか | 取り込み | i2c-controller でバスを持つ（標準） |
| SDA が固まったときにクロックと STOP を出すか | 取り込み | gpio で SDA を保つ（標準） |
| SDA が固まったところから回復できるか | DUT の戻り値、取り込み | SCL が k 回来たら離す（無し） |
| SMBus の PEC | DUT の判定 | i2c-target（PEC もバイトとして置く。標準） |
| データの n バイト目の NACK、ACK のポーリング | DUT の戻り値、取り込み | NACK（無し） |
| 特定のバイトでだけ伸ばす | 取り込み | ストレッチの指定（無し） |
| 10 ビットのアドレス、general call | 取り込み、相手の記録 | アドレスの拡張（無し） |
| 調停、途中の START や STOP（バスのエラー） | DUT の戻り値 | 反応する相手（無し、§3.1） |
| グリッチフィルタ（50 ns 以下のスパイク） | DUT の戻り値 | 難 |
| 立ち上がりの時間、オープンドレインを守っているか | 電圧 | 難 |

DUT が従のときは、i2c-controller が相手になる。probe がクロックを出すので、途中で切ることや時間の指定は probe 自身の時間で行える。

| 試験 | 判定 | 刺激、相手 |
|---|---|---|
| 受信、応答、書いてから repeated START で読む順、DUT が持つより多く読まれたとき | 相手の結果、DUT の報告 | i2c-controller（標準） |
| DUT のストレッチの長さ | 取り込み | i2c-controller（標準） |
| アドレスが合わないときの NACK、general call | 相手の結果 | i2c-controller（予約されたアドレスも送れる。標準） |
| 規格の下限の時間で送っても受けられるか | 相手の結果、取り込み | 時間の指定（無し） |
| 主がバイトの途中で消える、途中で START を出す | DUT の報告、次の転送 | 途中で切る（無し） |
| 10 ビットのアドレス、複数のアドレス | 相手の結果 | アドレスの拡張（無し） |

## 9. SPI

SPI の主は相手がいなくても線を動かすので、主が出す側の試験は判定だけで行える。

| 試験 | 判定 | 刺激、相手 |
|---|---|---|
| mode（CPOL と CPHA） | 取り込み: CS が有効になる前の SCK の level と、MOSI が変わるエッジ | 不要 |
| mode を変えたときの SCK | 取り込み: CS が有効になる前に、SCK が新しい level に落ち着いているか | 不要 |
| MOSI の値、ビット順、16 / 32 ビットの語のバイトの順 | 取り込み | 不要 |
| クロックの周波数 | 取り込み。取り込みより速いものは counter | 不要 |
| CS の時間、ハードウェアの CS（語ごとのパルスを含む）、DMA の転送の隙間、受信だけのモードのクロック数 | 取り込み | 不要 |
| MISO の受け取り、誤った CRC を見つけるか | DUT の報告 | spi-target（CRC もバイトとして置く。標準） |
| 長い転送の MISO | DUT の報告 | spi-target（長さは probe の宣言による。標準） |
| 続けざまの転送の MISO | DUT の報告 | 応答の列（無し） |
| 3 線式、共有バスで複数のデバイス | 取り込み、DUT の報告 | 線の拡張（無し） |
| MISO を取り込む時点の余裕 | DUT の報告 | 難 |
| QSPI のメモリマップ、SPI flash の読み出し | DUT の報告 | 反応する相手（無し、§3.1） |

相手が受けたデータでは、mode 0 と 3、mode 1 と 2 を区別できない（データを取り込むエッジが同じ）。mode は取り込みで判定する。

DUT が従のときは、spi-controller が相手になる。

| 試験 | 判定 | 刺激、相手 |
|---|---|---|
| DUT が受けた値、出す MISO、mode、ビット順 | 相手の記録、取り込み | spi-controller（標準） |
| CS から最初のビットまでの準備時間の下限、転送の間の最小の時間、オーバーラン | 相手の記録、DUT の報告 | spi-controller（setup_ns、gap_ns を変えていく。標準） |
| DUT が受けられる最高のクロック | 相手の記録 | spi-controller（probe の max_clock_hz まで。標準） |
| CS が無効な間に MISO を離しているか | 取り込み、電圧 | MISO に弱いプルをかける（無し） |
| CS をバイトの途中で切る、3 線式 | DUT の報告 | 主の拡張（無し） |

| 試験 | 判定 | 刺激、相手 |
|---|---|---|

| 比較器の応答の速さ | 取り込み | アナログの波形（無し） |
| オペアンプの利得 | アナログの取り込み | dac（標準） |

## 12. 1 本の線のプロトコル

| 試験 | 判定 | 刺激、相手 |
|---|---|---|
| RGB LED（WS2812 など）のビットの時間とリセットの時間 | 取り込み | 不要 |
| IR の送信（変調の周波数とデューティ、NEC などの符号） | 取り込み、counter | 不要 |
| IR の受信（受光モジュールの出力を受ける） | DUT の報告 | パターンの出力（無し） |
| 1-Wire のリセットのパルス、主の書き込みのスロット | 取り込み | 不要 |
| 1-Wire の存在のパルス、読み出し、ROM の検索 | DUT の報告、取り込み | 反応する相手（無し: 主のエッジから数 µs のうちに答える） |
| DMX（UART と break） | 取り込み（送る側）、DUT の報告（受ける側） | 受ける側はパターンの出力（無し） |

## 13. I2S と音

| 試験 | 判定 | 刺激、相手 |
|---|---|---|
| DUT が主で送る（BCLK、WS、データ、形式、サンプルの速さ） | 取り込み | 不要 |
| DUT が主で受ける | DUT の報告 | 反応する相手（無し: DUT のクロックに合わせてデータを出す） |
| DUT が従 | DUT の報告、取り込み | 反応する相手（無し: クロックと WS を出し、データを出す） |

## 14. CAN と LIN

| 試験 | 判定 | 刺激、相手 |
|---|---|---|
| CAN のビットの時間、フレーム（DUT のループバックか、聞くだけのモード） | 取り込み（DUT の TX のピン） | 不要 |
| CAN のバスでの送受信、ACK、調停、誤りのフレーム | DUT の報告、取り込み | 反応する相手（無し）とトランシーバ |
| LIN の主の break、同期、ヘッダ | 取り込み | 不要 |
| LIN の従として受ける | DUT の報告 | パターンの出力と uart（無し） |

## 15. 並列のバスと、OEP の相手の外のもの

| 周辺 | 判定 | 刺激、相手 |
|---|---|---|
| LCD の 8080 / 6800 の並列のバス（DUT が出す） | 取り込み（線の数だけチャネルが要る） | 不要 |
| FSMC / FMC の SRAM | DUT の報告 | 反応する相手（無し、§3.1） |
| SD カード（SPI のモード、SD のバスのモード）、FAT のファイル操作 | DUT の報告、取り込み | 反応する相手（無し、§3.1）。中身は FAT のイメージとして持つ |
| DVP（カメラの入力） | DUT の報告 | 速いパターンの出力（無し） |
| USB、Ethernet、USB PD | DUT の報告、取り込み（低速のものの解析） | 相手は PC、PD の電源。OEP は電源とリセットのピン、取り込みで助ける |
| タッチキー | DUT の報告 | 難（静電容量を変える回路が要る） |

## 16. 原理的に難しいもの

probe の作り方によらず難しいもの。受けたものに応じて答える相手は、DUT が待つ時間しだいで作れるので、ここには入れない（§3.1）。

1. **ns 単位の時間**（SPI の取り込みの余裕、デッドタイム、50 ns 以下のスパイクを無視するフィルタ）。
   - 出す側と測る側の両方に、数 ns の分解能が要る。
2. **電気的なこと**（出力の強さ、スルーレート、立ち上がりの時間、入力のインピーダンス、耐圧）。
   - アナログの取り込みの帯域の内だけで、回路を変える治具が要るものもある。
3. **物理量**（静電容量、温度）。治具の回路で作り、probe はその切り替えだけを受け持つ。
